The control loop

memory-repair-lab

The model never learns; the notes do. Retrieval failures are filed as typed notes, repairs cite the failure that motivated them, and generations are re-measured against a held-out split sealed before generation zero.

held-out recall 8/10 → 10/10; blind placebo arm, same budget: unchanged
published on purpose: a Goodhart arm that games recall and pays for it in tokens
walkthrough source

Every number above is regenerated by each repo's own CI on Windows and Linux — the committed artifacts are the claims, and the drift gate proves they regenerate. How I work

The habits are the résumé. These are the laws every repo above obeys — and they are the same instincts that keep a bank's critical applications reliable, pointed at AI.

Claims are treated like SLOs.

Each published number ships with its measurement command and its honest caveat in the same table row, rendered from metrics — never typed by hand. If regeneration disagrees, the build fails loudly.

Losses publish above the fold.

The crossover where the design loses, the deliberate blind spot, the flipped verdicts — leading with the boundary is what makes the rest of the page believable.

Every deletion carries its reason.

Kill ledgers, prune records, repair citations: an unrecorded decision gets re-litigated in a month by someone who never saw it die. Audit trails are a product feature, not paperwork.

Demos run where the customer is.

Every project installs with nothing, runs in seconds with zero API keys, and carries a walkthrough a stakeholder can click through — because the room where engineering meets the customer is where systems earn trust or lose it.

Hard things get explained simply.

Recipe boxes, smoke alarms, courtrooms, sealed envelopes: if I can't explain the system to the person who depends on it, the system isn't finished.
