Mutation lab

The question: a green test suite tells you the tests passed. It does not tell you the tests would have noticed if the code were wrong. This page finds out, by breaking game.html on purpose - one seeded defect at a time - and reporting how many of them the game's own suite catches.

Every mutation is an exact string replacement listed in tools/mutations.json. For each one, this page rebuilds the whole file in memory, runs all of its tests in a sandboxed iframe, and records whether any test failed. A defect that no test notices is a hole, and it is named below.

This page needs to be served over http so it can fetch the game file. From the repository root: python -m http.server 8000, then open http://localhost:8000/tools/mutation-lab.html. Opening it straight off disk will fail at the first fetch.

How to read this

KILLED means at least one test failed when the defect was present - the suite was watching. SURVIVED means all tests passed with a real defect in the code. Survivors are the interesting rows: each one is a statement about something this project believes and does not check.

The kill rate is not a score to maximise by deleting hard mutations. The catalogue is committed, so it can only grow, and every survivor stays in the file after it is fixed - a fixed hole that quietly left the catalogue would make the next number a lie.
